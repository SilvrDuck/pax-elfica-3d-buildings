# Working on this repo (Codex, Claude Code, humans)

3D dollhouse of the Auberge de l'Épée (*Pax Elfica*, a French TTRPG by Les XII Singes), shown by the
DM on one screen at the table. Read `README.md` first for what it does and how to run it. The design
is in `docs/superpowers/specs/2026-10-18-auberge-epee-3d-design.md` and the build plan in
`docs/superpowers/plans/2026-10-18-auberge-epee-3d.md`; both are the authority when a choice here
seems arbitrary.

## Ground rules

- **Public repo, nothing copyrighted.** Never commit the official plans, crops of them
  (`public/plans/` is ignored), rulebook scans, or anything from the XII Singes visual pack. Room
  names and dimensions from the rulebook are facts and are fine. 3D models must be CC0 and listed in
  `public/assets/LICENSES.md` by `tools/pick-assets.mjs`.
- **The official plans win.** Geometry is traced from `Officiel/Plans_batiments/*.jpg` (not in the
  repo; see README for where they are expected). Tolerance: wall centrelines and openings within
  0.25 m, furniture within 0.5 m. The in-app calque (key `C`) and `node tools/grid-view.mjs <level>
  <col> <row> <cols> <rows> --walls` are how you check.
- **Edit the scripts, not the JSON.** `src/data/levels/*.json` are generated by
  `tools/levels/<level>.mjs`, written in plan-grid cells (1 cell = 1.5 m) with the helpers in
  `tools/lib/author.mjs`. Change the script, rerun it, commit both.
- **UI copy is French.** Level labels, buttons, labels, console messages shown to the DM.
- **Tests first.** Vitest under `tests/`; `npm test` must stay green, `npm run test:legend` must keep
  all 39 legend rooms placed exactly once. New behaviour gets a failing test before the code.
- **Commits**: Conventional Commits (`feat:`, `fix:`, `docs:`…), imperative, no AI attribution
  trailers or signatures of any kind.
- **Write as if from the final spec**: no comments or names that narrate how something was changed.

## Working in parallel

Several agents work on this repo at once. The issue tracker is the plan:
<https://github.com/SilvrDuck/pax-elfica-3d-buildings/issues>.

- Take one issue at a time. Issues labelled `prêt` have no dependency; `bloqué` ones name what they
  wait on in their body. Assign yourself and comment « en cours » before starting, so nobody else
  takes it.
- Labels say who is expected to pick an issue up: `visuel` (look, lighting, models, UI),
  `moteur` (Three.js engine, builders, performance), `données` (level data against the plans),
  `infra`.
- Branch from `main`, named `feature/<issue>-<slug>` or `fix/<issue>-<slug>`. Never push to
  `main` directly; open a pull request that says `Closes #<issue>`, with before/after screenshots
  from `npm run shots <level>` for anything visual. CI must be green (`npm test`,
  `npm run test:legend`, `npm run build`).
- Each issue names the files it is expected to touch. Stay inside them; if you need a change
  elsewhere, write it in the PR description or open an issue rather than editing a file another
  branch owns.
- Keep PRs small enough to review in ten minutes. Rebase on `main` before asking for review.

## Layout

| Path | Role |
|---|---|
| `src/main.js` | Boot: scene, levels, props, selector, keys, URL params (`level`, `calque`, `labels`, `view=top`) |
| `src/scene.js`, `src/lighting.js`, `src/materials.js` | Renderer and camera, dusk lighting, flat palette (one material per name and level, so levels fade independently) |
| `src/stack.js` | `LevelStack`: one group per level at its elevation, roofs grouped by the storey they cover, peeling with a 300 ms fade, merged geometry per level |
| `src/build/*` | Pure builders: walls with openings, floors, gable and pyramid roofs, stairs, silo shaft, merge pass |
| `src/props.js`, `src/data/props.json` | glTF prop catalogue with real-world footprints; a missing model becomes a box |
| `src/calque.js`, `src/labels.js` | Plan overlay and room-name labels for the selected level |
| `src/data/levels.js`, `schema.js`, `legend.js` | Level registry (ids, elevations), JSON validator, rulebook room legend |
| `tools/calibrate.mjs` | Measures the plan grid (179 px/cell), registers the sheets onto the RdC frame, cuts calque crops, writes `src/data/calibration.json` |
| `tools/levels/*.mjs`, `tools/lib/author.mjs` | Level authoring in cells |
| `tools/grid-view.mjs`, `tools/overlay.mjs` | Plan views with the grid, optionally with the model's walls |
| `tools/shots.mjs` | Headless Chromium screenshots of every level into `verification/` |
| `tools/fetch-assets.sh`, `tools/pick-assets.mjs` | CC0 packs into `vendor/` (ignored), used pieces into `public/assets/` |

## Conventions that are easy to get wrong

- World frame: metres, origin at the top-left pixel of the RdC sheet, x east, z south, y up.
  `calibration.gridOrigin` is where cell (0, 0) starts.
- Level elevations are fixed in `src/data/levels.js` (RdC 0, 1er 3.0, 2e 6.0, 3e 8.6, 4e 11.2,
  silos −5 and −10). Every block of the inn shares them; a "level" is every block's storey at that
  height.
- A roof entry carries `covers: <levelId>`; it is shown only while the selected level is above that
  storey. Put a roof in the JSON of the first level above the block it covers.
- Wall thickness comes from the material (`enclosure` 0.6, `stone` 0.5, `timber`/`cob` 0.3,
  `partition` 0.2), never from the drawing.
- The upper-floor sheet draws the tower and north wall about half a metre off the lower sheets;
  shells stay stacked on the RdC shell, only partitions and furniture follow that sheet.
- Budget: under 400 draw calls at `toits` on an integrated GPU (key `F` shows the counter).
